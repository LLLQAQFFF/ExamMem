# ExamMem 学术投稿可行性评估

评估日期：2026-09-05。结论基于论文、上游 Git 快照、当前源码与已有实验摘要的审查，不是本轮重新运行实验的结果。

## 1. 决策结论

- ACL 2026 已结束，不能再投稿。本体研究方向与 ACL 的 agents、交互系统、教育 NLP、记忆评测方向相符。
- 当前更适合准备系统演示论文；研究主会/Findings 方向有潜力，但现有创新定位与实验不足以支撑强结论。不提供没有依据的录用概率。
- 不建议继续堆产品功能或仅更换论文术语。优先补公平对比、独立数据与教学决策实验。
- 推荐主问题：**在带噪声、跨会话、会被纠正的学习证据中，如何区分短暂失误与持续知识变化，维护可审计的当前学习状态，并减少错误教学决策？**

ACL 2026 主会 ARR 截止日为 2026-01-05，会议日期为 07-02 至 07-07；Demo 截止日为 02-27。见[主会征稿](https://2026.aclweb.org/calls/main_conference_papers/)和[Demo 征稿](https://2026.aclweb.org/calls/system_demonstration/)。

近期可考虑 EACL 2027 Demo：2026-09-22 截止，要求论文、最多 2.5 分钟视频、在线演示或可安装包；正文最多 6 页，要求验证系统用途或质量的证据。它是系统演示赛道，不等于主会研究论文，也不保证录用。见[官方征稿](https://2027.eacl.org/calls/demos/)。

## 3. 上游已有能力：必须明确归属

DeepTutor 已将解题、出题与学习者画像闭环连接；动态记忆包括 Trace Forest、跨会话薄弱点分析与画像注入。其论文还包含模拟学生评测、组件消融与人工偏好对齐，不能把 ExamMem 的离线状态准确率与其教学质量分数横向比较。见[原论文 v1](https://arxiv.org/html/2604.26962v1)和[修订版 v3](https://arxiv.org/html/2604.26962v3)。

源码提供了额外确认：

- `origin/eval:src/personalization/prompts/en/weakness_agent.yaml` 已要求检索历史错题与重复提问，维护 Active/Resolved 薄弱点及跨会话证据，并保留旧条目。
- `origin/eval:src/personalization/trace_tools.py` 已支持历史检索、详情读取和文档更新。
- `origin/main:deeptutor/services/memory/consolidator/modes/update.py` 从 snapshot entity 提取新事实。
- 同版本 `prompts/en/update_l2.yaml` 要求来源引用；`audit_l2.yaml` 已支持基于原始证据替换、删除、插入。因此不能宣称原生记忆“只追加、不可纠正、没有溯源”。

论文 Trace Forest 的三个粒度、新版 Native 的 L1/L2/L3、ExamMem 的事件/状态/投影是不同分层，不能仅因名称相近就当作同一种模型。

ExamMem 可归属的增量主要是：考试领域的 typed slot、学习证据门控、显式争议与版本状态、可重建学习画像，以及与练习/复核的受控集成。插件化、PostgreSQL、事务和前端是实现基础，不自动构成算法创新。

## 4. 最接近的相关工作与新颖性压力

| 相关工作 | 与 ExamMem 的重叠 | 需要建立的差异 |
| --- | --- | --- |
| DeepTutor | 个性化学习、历史证据、薄弱点更新、练习闭环 | typed 证据政策如何比提示词驱动画像更稳健 |
| ScaffoldLM，ACL 2026 | 评估驱动记忆、学习者状态、教学动作 | 跨会话长期状态与错误证据修正，而非只描述评估闭环 |
| MemoryLACE，2026-09-02 预印本 | merge/supersession/contradiction、provenance、生命周期检索 | 学习证据的可靠性、独立性、短暂失误、修正后决策效应 |
| A-MEM / Mem0 | 动态记忆组织、更新与检索 | 相同信息与预算下，对学习状态变化的独立增益 |
| LongMemEval / V2 | 长期交互记忆评测 | 教育状态变化与教学决策的特有任务价值 |
| Knowledge Tracing | 从作答序列推断掌握状态 | 与 BKT/DKT 等适配比较，不能将规则分数称为已校准掌握概率 |

[ScaffoldLM](https://aclanthology.org/2026.acl-long.325/)用评估驱动记忆组织多轮数学辅导，是“学习计划＋评估＋记忆”叙事的直接近邻。

[MemoryLACE](https://arxiv.org/html/2609.03201v1)显式维护合并、替代和冲突关系，并在检索时组织关联证据。它虽是新预印本，仍必须作为相关工作讨论；仅靠这些操作名称无法主张首创。

其他参考：[A-MEM](https://arxiv.org/abs/2502.12110)、[Mem0](https://arxiv.org/abs/2504.19413)、[LongMemEval](https://arxiv.org/abs/2410.10813)、[LongMemEval-V2](https://arxiv.org/abs/2605.12493)、[知识追踪综述](https://arxiv.org/abs/2201.06953)、[对话中的难度感知知识追踪](https://aclanthology.org/2026.bea-1.43/)。这是一轮针对性文献审查，不是穷尽性新颖性证明。

## 5. 当前实现能支持怎样的方法描述

实际核心调用链：

```text
作答 → Grader → ErrorAnalyzer → LearningEvent / typed candidate
→ L1 事件记录 → 相同 Scope/slot 候选
→ 受约束语义关系分类或确定性 mastery 比较
→ 证据评分与生命周期策略
→ 事务内版本写入、CAS、来源与审计
→ 提交后 L3 重建
→ 推荐或已绑定教学上下文
```

| 方法组成 | 源码 | 研究价值与限制 |
| --- | --- | --- |
| 语义判断与状态写入分离 | `exam_mem/lifecycle/relation_classifier.py`、`state_machine.py` | LLM 仅返回候选序号/关系；确定性代码决定状态操作。可测对错误分类与越界输出的稳健性，但不是天然新算法 |
| 学习证据累积 | `policy_v1.py`、`contracts.py` | 置信度、难度、错因、时间衰减、事件数/会话数/支持差共同门控；需要验证规则与阈值的有效性 |
| 可追溯状态更新 | `applier.py`、`compensation.py`、`storage/rebuild.py` | 当前状态与来源版本可审计；事务可靠性与教育语义正确性必须分别评估 |
| 有约束的记忆检索 | `exam_mem/retrieval/service.py` | 显式约束、重排和可变 0..K；属于完整系统贡献，不能把现有模型和阈值组合直接称为新检索算法 |

现有策略是工程启发式：默认至少 3 条方向性证据、2 个会话、置信度 0.70、支持差 0.15；时间半衰期 30 天。`practice/memory.py` 按作答正确与否构造 1.0/0.0 mastery 候选。它目前不是经真实数据拟合或校准的连续认知状态估计器。

普通 Chat 的 `learning_observation.py` 明确不写正式掌握记忆。因此不能在论文中描述成“任意聊天自动更新权威掌握度”。自然语言端到端实验应从真实作答、评分、诊断这条已存在的入口开始。

可保留三个**待验证贡献候选**：

1. 面向学习证据的可信状态修订：避免把偶然失误、低置信结论或重复事件当成稳定知识变化。
2. 受约束语义判别与可执行证据政策结合：在保留争议和来源的情况下更新状态，并让后续教学只消费合适证据。
3. 教育长期记忆评测协议：同时评估状态维护与后续教学决策；当前模板集可作为单元级压力测试基础，独立 benchmark 尚需补建。

## 6. 已有结果：哪些可以用，哪些不能外推

| 结果 | 当前证据 | 允许结论 |
| --- | --- | --- |
| v1 操作准确率 95.73%，状态 exact 90.42% | 80 条 frozen 结构化轨迹，79 条完成 | 已知正确上游事件时，策略具备一定状态维护能力 |
| v3 操作准确率 94.47%，状态 exact 89.17% | 80 条计算机学科轨迹，78 条完成 | 相同生命周期形状下的跨学科内容迁移检查 |
| v3 推荐准确率 80.83%，其他四臂 55% | 同一推荐器只有 Lifecycle 获得 typed 状态 | 只能说明当前集成链路表现；不足以证明胜过完整 Native、RAG 或其他记忆算法 |
| 检索 Recall@5 95.47%，拒答准确率 98.33% | 报告中的 310 条查询 | 支持特定检索集表现，不代表学习增益或全部运行模式 |

来源：[v1 报告](./evaluation/stage09-frozen-test.md)、[v3 报告](./evaluation/controlled-v3-frozen-test.zh-CN.md)、[检索报告](./evaluation/semantic-retrieval-v2-remediation.zh-CN.md)。

必须修正或披露的问题：

1. **Native v3 没跑到完整记忆路径。** 评测客户端写 L1 JSONL，而新 consolidator 读 snapshot entity；该轮 Native 的 L2/L3 和 LLM 调用没有发生。v1 曾记录 680 次 Native 调用，不能将 v3 的故障概括为所有历史版本均未运行。
2. **推荐对比不对称。** `evaluation/backend_adapters.py` 的 Native `recommend()` 不传记忆，Postgres session 也仅在 Lifecycle 分支填充 model/evidence。四个基线的相同分数包含接口缺失效应。
3. **内部状态契约偏向本实现。** append-only 不执行版本收敛，用 exact lifecycle state 测它，不能替代其下游 QA/决策质量。应分开报机制正确性与共同外部任务质量。
4. **当前不是端到端 NLP 评测。** 输入是正确的结构化事件与 Gold-normalized slot，未测评分、错因、证据置信度或抽取误差如何传播。
5. **跨域独立性有限。** v3 沿用 v1 的 12 类形状；构造器依赖每类两个模板。学科更换不等于未见任务结构泛化。v2 已被审计判为无效跨学科证据，不应恢复为正面结果。
6. **不同版本不是前后可比实验。** v1 的 30.83% 推荐分数与 v3 的 80.83%来自不同数据/代码，不能相减声称改进了 50 个百分点。
7. **检索 test 已参与问题诊断。** 报告称阈值仅用 dev 选择，但同一 test 的失败分布已用于指导修复方向。论文应披露，并新增完全独立的最终 test；未改 test 文件不等于方法开发未受 test 影响。
8. **工程门槛不等于科学发现。** 零越界是有限样例观察；10k 索引路径 p95 64.77 ms 对 exact 56.87 ms，不能宣称已证明生产加速。模型费用缺失时不能用调用次数替代美元成本。

## 7. 补什么：按研究价值排序

### P0：先做能决定是否值得投主会的实验

1. 修复 Native 适配器，锁定原生代码版本，验收 L2/L3 有效生成与被实际消费；论文期实现和新版 Native 分开命名。
2. 建立共同的下游接口：所有系统都能把自己的记忆交给相同决策模型，控制输入历史、骨干模型、token 预算、问题与评分协议。必要的格式转换对所有方法公开且不读取 Gold。
3. 增加强基线：完整 DeepTutor、时间感知 RAG、同 slot 最新证据覆盖、纯 LLM 更新；再选 Mem0/A-MEM，以及可复现的 MemoryLACE。掌握预测任务另加 BKT/DKT 等适配基线，避免强行比较不同输出任务。
4. 小规模独立盲测先验证：真实变化、偶然失误、重复作答、错误评分后纠正、未解冲突等场景中，ExamMem 是否比简单最新覆盖与强 RAG 更好。若没有稳定收益，优先走 Demo，避免扩大无效实验。

### P1：使研究论证成立

- **独立数据：** 由未参与策略设计的标注者审查原始作答/对话；标注证据、变化、争议和合理下一步，允许不确定/多个合理动作。报告一致性与裁决过程。按学习者、知识点及场景组合隔离切分；新域新增情节，不只替换术语。
- **两层实验：** oracle 事件层隔离状态政策；真实作答→评分→诊断→记忆→建议层测误差传播。故意增加错误评分、缺失证据、低置信、延迟事件和重复投递。
- **关键消融：** 去证据门控、最新覆盖替代争议状态、去置信度/时间项、LLM 直接决定操作、去检索门控。其他部分固定，避免混入换模型收益。低置信度应报告校准，不能直接相信 LLM 自报数值。
- **共同外部指标：** 当前状态问答、变更/纠错后答案、证据引用正确率、误推荐与遗漏推荐、错误旧证据在教学输出中的使用率。内部 operation accuracy 单列。
- **统计与成本：** 以学习轨迹而非同轨迹多个 checkpoint 作为重采样单位，报告配对 bootstrap 置信区间、各场景表现、失败样例、多骨干稳定性、端到端时延与真实可获得的 token 统计。
- **主张约束：** 若声称提高学习效果，补真实学生前测/后测和延迟保持测试，采用合理对照与样本量规划。若仅声称状态维护更准，可用独立人工标签和下游决策验证，不必先强做大规模教学试验。

### P2：论文与演示整理

- 论文以研究问题、失败实例、方法、对照、结果和局限组织；框架和 UI 只介绍支撑实验所需部分。
- 明确标注 DeepTutor 为依赖/宿主，保留归属和许可证；不要将上游 RAG、出题、学习路径重新宣称为原创。
- 锁定环境、commit、模型、数据 manifest、prompt 与重现命令；审查后发布必要的去标识逐例输出，使人能核对均值和错误。
- Demo 展示一条有辨识度的流程：旧薄弱点→一次偶然失误→多次可靠新证据→争议/修订→推荐变化→来源解释；另做错误判断后的复核示例。只演示已有且验证过的行为。

## 8. 建议论文定位

暂定研究题目：**ExamMem: Evidence-Gated Learner State Revision for Longitudinal Tutoring**。

核心假设：在相同信息与推理预算下，学习证据的质量和跨会话支持门控，能比直接覆盖或无约束总结更好地保持当前学习状态，并减少由旧状态或错误证据触发的教学决策。

这是假设，不是现有实验已经证明的结论。最有价值的下一步是公平地验证它；若只能证明可追溯、易操作和系统完整，则将论文定位为可审计学习记忆系统的 Demo，而不是宣称新的通用记忆算法。
