# 教材库与基于教材学习需求规格

- 状态：待实现设计基线
- 适用范围：ExamMem 智能备考插件
- 计划拆分：Checkpoint 1「教材库与结构化摄取」；Checkpoint 2「教材绑定与基于教材教学」

## 1. 背景与目标

当前学习计划导入会从文件或 URL 中提取考试科目、章节和叶子知识点，但导入材料仅用于生成结构，后续进入学习会话时没有持续绑定原教材。学习主要由 LLM 根据知识点标题和 ExamMem 学习记忆组织，无法稳定回答以下问题：

- 这次讲解依据哪一本教材、哪个版本、哪一章和哪一页？
- 超大教材如何检索，而不是把整本书塞进上下文？
- 一个学习计划如何使用零本、一本或多本教材？
- 教材之间冲突时，出题、判题和教学采用哪个来源？
- 学习计划更新、教材换版后，历史学习和考试是否仍可追溯？

本需求在现有闭环上增加两个能力：

1. 将用户教材解析为保留原始目录层级、版本和来源定位的教材库。
2. 将教材显式绑定到学习计划，在知识点学习、出题和复盘时按权限检索并引用教材证据。

最终产品定位从“LLM 根据知识点标题进行通用讲解”提升为：

> 教材提供可追溯的知识依据，LLM 负责检索、组织、解释和教学；ExamMem 负责考试范围、学习关系、正式练习与长期学习记忆。

## 2. 术语与不可混淆的对象

| 对象 | 含义 | 所有者 |
| --- | --- | --- |
| 教材 | 用户上传并管理的学习资料逻辑实体 | ExamMem |
| 教材版本 | 某次不可变的教材内容快照，由文件哈希和解析版本标识 | ExamMem 元数据；原文由 Host 保存 |
| 教材章节树 | 教材天然的篇、章、节、小节结构 | ExamMem 保存可查询结构及 Host 来源引用 |
| 检索片段 | 为 RAG 创建的可重建文本片段和向量 | DeepTutor Host |
| 学习计划 Taxonomy | 面向考试的科目、模块、知识点层级 | ExamMem |
| 知识点—教材映射 | 某个 Taxonomy 知识点对应哪些教材章节 | ExamMem |
| Learning Memory | 用户正式作答、掌握度、错误模式和推荐形成的 L1/L2/L3 记忆 | ExamMem |

教材章节树与学习计划 Taxonomy 必须保持独立：教材按作者组织内容，考试按考查范围组织知识点，两者可以多对多映射，但不能共用 ID、互相覆盖或被静默合并。

## 3. 产品和架构原则

### 3.1 必须保持的不变量

- DeepTutor Core 不得直接 import `exam_mem`。
- ExamMem 继续通过中性 Plugin API 使用文件解析、来源存储、RAG 和会话能力。
- ExamMem 使用自有 PostgreSQL 保存教材领域关系，不直接读写 DeepTutor 内部数据库或 Native Memory。
- 原始教材、解析产物和向量索引由 Host 管理；ExamMem 仅保存不透明 Host 引用和领域元数据。
- 已存在的 ExamMem migration 文件不得修改；新增表通过新的顺序 migration 创建。
- 教材原文、教材观点和 Learning Memory 不能混为一体。Learning Memory 记录用户学习证据，不把教材陈述写成用户已掌握事实。
- 大纲版本、教材版本、试卷版本和作答版本均不可被后续更新覆盖。
- 多教材内容不得在入库时融合成失去来源的“统一教材”。
- 未绑定教材时允许继续使用现有通用 LLM 学习，但 UI 和响应必须明确标记“未绑定教材”，不得伪装成教材依据。

### 3.2 复用 DeepTutor 与 ExamMem 新增内容

| 能力 | 处理方式 |
| --- | --- |
| 文件上传、原始来源存储 | 复用 DeepTutor Host |
| PDF/TXT/Markdown 解析 | 复用 DeepTutor ParseService |
| Markdown、结构块和资源产物 | 复用 DeepTutor 解析契约 |
| 文本切片、Embedding、向量检索 | 复用并中性增强 DeepTutor RAG |
| Chat / mastery_path 教学会话 | 复用 DeepTutor |
| 教材目录、版本、处理状态 | ExamMem 新增 |
| 学习计划与教材绑定 | ExamMem 新增 |
| 知识点与教材章节映射 | ExamMem 新增 |
| 教材优先级与冲突治理 | ExamMem 新增 |
| 练习、判题、记忆生命周期 | 保持现有 ExamMem 闭环 |

### 3.3 总体调用链

```text
教材上传
  → DeepTutor Host 保存原始来源
  → ParseService 生成 markdown + structured blocks
  → ExamMem 恢复并确认教材章节树
  → Host 按章节感知方式切片和建立 RAG 索引
  → ExamMem 保存教材版本、章节结构和 Host 引用

学习计划知识点
  → 解析当前学习计划版本
  → 查找显式绑定的 0..N 本教材
  → 查找知识点—教材章节映射
  → Host 在许可章节内检索、重排并返回证据
  → DeepTutor mastery_path 基于证据教学并展示引用
  → 正式练习继续进入 Grade → Diagnosis → Memory → Recommendation
```

## 4. Checkpoint 1：教材库与结构化摄取

### 4.1 目标

建立可长期管理的“教材库”，把教材解析成保留原始结构、可版本化、可恢复、可检索且可追溯的知识来源。本阶段不改变学习会话，也不自动将教材绑定到学习计划。

### 4.2 前置假设

- 第一版支持 DeepTutor 当前稳定解析的 PDF、TXT、Markdown；URL 教材、网页集合和视频不在本阶段范围内。
- 文本型 PDF 是基线能力；扫描 PDF 可以进入 OCR 路径，但低置信度结果必须可见，不能静默当作准确正文。
- 用户只可以访问自己有权访问的教材及其索引。
- 教材数据库不是新的向量数据库实现；向量能力继续复用 Host。

### 4.3 产品需求

#### 4.3.1 教材库页面

- 在智能备考中增加“教材库”，避免与 DeepTutor 原有生成式“书籍”功能混淆。
- 支持上传教材、查看教材列表、处理状态、文件类型、大小、版本、章节数和最近更新时间。
- 支持打开教材详情查看原始目录层级、页码范围、解析警告和索引状态。
- 支持同一教材创建新版本；旧版本保持可查，不覆盖历史绑定。
- 失败任务展示明确阶段和可恢复操作，不显示无限加载或模糊的“处理失败”。
- 本阶段允许归档教材，但不做物理删除；已被学习计划或历史试卷引用的版本仍必须可追溯。

#### 4.3.2 结构保真

- 尽可能保留篇、章、节、小节的顺序、标题、层级、页码和父子关系。
- 切片只能发生在章节内部；每个片段必须携带完整章节路径和来源定位。
- 表格、公式、图片说明和脚注如果解析器能够识别，应保留其结构或明确标记类型。
- 没有可靠目录时，可以生成“候选章节树”，但必须标记为推断结果并允许用户确认；不得把固定长度切片冒充教材目录。
- 解析结构必须确定性排序，同一源文件和同一解析器版本重复执行应得到相同章节标识。

#### 4.3.3 大教材处理

- 禁止把完整教材放入单次 LLM 上下文。
- 摄取采用分阶段任务：保存 → 解析 → 构建章节树 → 切片 → 索引 → 完成。
- 每个阶段记录 checkpoint、进度、输入哈希、输出引用、错误码和重试次数。
- 重复提交相同文件必须通过内容哈希识别，避免重复索引；用户明确要求时可复用已有版本或创建新的逻辑教材。
- 索引失败不能破坏已成功保存的原始来源和章节结构，重试从最近安全 checkpoint 继续。
- 进度必须来自真实处理阶段或已处理单元数，不能使用与后台无关的模拟百分比。
- 大文件处理不能依赖一个持续数分钟的浏览器 HTTP 连接；客户端通过任务状态查询或事件流观察进度。

### 4.4 逻辑数据模型

以下为领域模型，不在本需求中锁定最终表名和字段类型：

| 模型 | 关键内容 |
| --- | --- |
| `textbook` | 所有者、标题、作者/出版社等可选信息、状态、归档时间 |
| `textbook_version` | 教材 ID、版本号、内容哈希、Host 原始来源引用、解析器签名、处理状态、创建时间 |
| `textbook_section` | 版本 ID、稳定 section key、父节点、层级、顺序、标题、页码范围、Host 内容引用、解析置信度 |
| `textbook_ingestion_job` | 幂等键、当前阶段、进度、checkpoint、错误码、开始/完成时间 |

约束：

- `textbook_version` 一经完成不得原地修改内容；重新上传或重新解析产生新版本或新的解析产物版本。
- `textbook_section` 的稳定标识至少由教材版本、规范化章节路径和顺序信息确定。
- 数据库不保存向量；索引只通过 Host reference 访问。
- 原始文件引用和索引引用必须支持权限检查与失效检测。

### 4.5 技术方案

#### 4.5.1 解析与章节恢复

1. Host 保存原文件并计算内容哈希。
2. DeepTutor ParseService 返回 Markdown、structured blocks、资源目录和 parser signature。
3. 优先使用解析器识别的标题块、PDF 书签、目录和页码恢复章节树。
4. 结构证据不足时由结构提取器产生候选树，并保存推断置信度和原始定位。
5. 用户确认后的章节树形成不可变教材版本结构。

LLM 可以辅助识别标题和层级，但不能凭空改写教材内容，也不能丢弃原始块定位。

#### 4.5.2 章节感知索引

- 每个章节先形成独立文档单元，再在章节内部做带重叠的语义切片。
- 片段 metadata 至少包含教材、教材版本、section key、完整章节路径、页码范围、片段顺序和原始来源引用。
- 索引必须可以从原始来源与结构元数据重建，因此属于 L3 类似的可重建基础设施，不是业务真相。
- 第一版可以使用 DeepTutor 已有 Embedding 和向量后端，但需要中性方式补齐结构 metadata，不能在 Core 中加入 `if exam_mem`。

#### 4.5.3 中性 Host 接口

需要通过插件接口提供以下领域无关能力：

- 保存并解析来源，返回不透明 source reference 和结构化解析结果。
- 创建、查询、重试和重建知识索引。
- 按 source/section metadata 约束检索范围。
- 查询处理状态和索引版本。

接口只表达“结构化来源”和“知识索引”，不出现 ExamMem、教材、考试或知识点等领域名称。

### 4.6 预期难点与处理原则

| 难点 | 风险 | 处理原则 |
| --- | --- | --- |
| PDF 目录与正文标题不一致 | 章节层级错误 | 保留多种结构证据、展示置信度、允许确认 |
| 扫描 PDF / OCR | 错字影响检索和教学 | 标记 OCR 与置信度；低置信度引用必须可见 |
| 表格、公式、跨页段落 | 内容被错误切开 | 使用 structured blocks 和页码，不只按字符切片 |
| 超大教材耗时和成本 | 请求超时、重复消费 Embedding | 异步任务、幂等哈希、分段 checkpoint、可恢复索引 |
| 重复或新版教材 | 数据膨胀、历史漂移 | 内容去重、不可变版本、引用固定到版本 |
| 用户权限 | 检索到其他用户教材 | source、index、binding 三层都校验所有者 |
| Host 索引丢失 | 教材不可用 | 原始来源和章节结构保留，索引可重建 |

### 4.7 Checkpoint 1 验收标准

#### 功能验收

- 用户能上传 PDF/TXT/Markdown 教材并在教材库看到真实处理状态。
- 教材详情能按层级展示章节树，并能定位到原始页码或来源片段。
- 同一本教材可以存在多个不可变版本，历史版本不被覆盖。
- 教材可以归档；被引用版本不会因归档丢失。
- 至少使用一份合法可测试的长文档验证分批处理，过程中浏览器连接中断后任务仍可继续查询和恢复。

#### 数据与可靠性验收

- 相同文件重复摄取不会重复创建向量内容或产生重复章节。
- 任一摄取阶段失败后可从安全 checkpoint 重试，且不会产生半完成的“可用”版本。
- 章节和片段均能追溯到教材 ID、版本、章节路径和原始来源。
- Host 索引删除后能够从保留数据重建，教材业务元数据不丢失。
- 权限测试证明用户不能列出、读取或检索其他用户教材。

#### 工程验收

- DeepTutor Core 不 import `exam_mem`，中性 Host Hook 有独立契约测试。
- ExamMem PostgreSQL migration 从当前 head 向后新增，既有 migration 内容与顺序保持不变。
- Repository/PostgreSQL 集成测试覆盖教材、版本、章节、任务状态、幂等和归档。
- 后端 lint、单元测试、集成测试和 Web production build 通过。
- 不绑定教材时，现有学习计划、Practice、Memory 和 Review 回归通过。

## 5. Checkpoint 2：教材绑定与基于教材教学

### 5.1 目标

允许一个学习计划版本显式绑定零本、一本或多本教材，将叶子知识点映射到教材章节；进入 DeepTutor 学习会话时自动检索对应教材证据，提供可引用、可比较、可恢复的教学，并为后续来源驱动出题建立固定证据边界。

### 5.2 前置假设

- Checkpoint 1 已提供可用教材版本、章节树、权限隔离和 RAG 索引。
- 学习计划已经发布，Taxonomy 与四维 Scope 继续是考试和记忆的正式范围。
- 教材绑定以学习计划版本为边界；计划发布新版本时不得静默继承不兼容映射。
- 第一版的自动推荐只是候选建议，最终绑定和权威优先级由用户确认。

### 5.3 产品需求

#### 5.3.1 学习计划与教材绑定

- 新建学习计划时支持“从教材库生成大纲”，但生成结果仍需走现有草稿、确认和发布流程。
- 学习计划详情支持绑定零本、一本或多本教材版本。
- 用户可以指定主教材、辅教材和参考资料的优先级，并随时查看绑定版本。
- 系统可根据知识点标题、章节语义和覆盖率推荐教材与章节，但不得自动确认绑定。
- 发布后的映射固定到学习计划版本和教材版本；调整映射需要显式生成新映射版本或随新计划版本发布。
- 计划或教材归档后，新的学习入口不再默认使用它，但历史会话、考试和复盘仍可读取原绑定证据。

#### 5.3.2 知识点—章节映射

- 一个知识点可以映射到同一本教材的多个章节，也可以跨多本教材映射。
- 一个章节可以支持多个知识点。
- 映射保存来源、置信度、创建方式（人工/推荐）和确认状态。
- 未确认映射不得作为正式出题、判题依据；教学时如允许使用，必须标记为候选来源。
- 页面应显示每个知识点已绑定教材数、章节数和覆盖状态。

#### 5.3.3 基于教材的学习会话

- 用户从知识点进入学习时，系统解析当前计划版本、知识点和已确认教材绑定。
- 第一次进入会话时，将知识点目标、章节范围、教材优先级和语言注入 mastery_path 会话。
- 再次进入同一知识点时恢复原会话和原教材版本；不得因教材库更新而静默切换来源。
- 回答应展示教材标题、版本、章节路径和页码/来源定位，并可打开证据片段。
- 检索不到证据时必须明确说明；是否继续使用通用 LLM 知识由产品配置决定，且回答必须区分教材依据和模型补充。
- 多教材模式支持“按主教材教学”和“比较教材观点”。

#### 5.3.4 多教材冲突治理

默认来源优先级：

```text
正式考试大纲
  → 用户指定主教材
  → 用户指定辅教材
  → 其他已绑定参考资料
  → LLM 通用知识
```

必须满足：

- 不同教材的片段和观点分别保存 provenance，不在入库阶段融合。
- 检索结果按来源分组，再按用户设置的权威等级和相关性重排。
- 高优先级来源与低优先级来源冲突时，以高优先级来源作为考试口径，同时展示冲突提示和双方证据。
- 同级权威来源冲突时，LLM 不得自行宣布唯一真相，应说明差异、适用条件和引用位置。
- 教材版本差异必须展示为版本差异，不能用新版本内容改写历史会话或历史评分。
- 自动冲突识别属于辅助判断；原始证据和优先级是最终可审计依据。

#### 5.3.5 与练习、判题和记忆的边界

- 本 Checkpoint 首要交付是“基于教材教学”；正式来源驱动出题可以接入已绑定证据，但不得重写现有 Practice workflow。
- 一旦题目声明基于教材生成，题目版本必须固定教材版本、章节和证据片段集合。
- 判题使用与题目相同的固定证据边界，不允许题目依据教材 A、评分时动态检索教材 B。
- 考试复盘展示题目所用教材证据和版本。
- L1 仍记录正式作答事实；L2/L3 仍表示用户掌握度和错误模式。教材内容只能作为 provenance，不能直接产生“用户已掌握”结论。
- 普通 Chat、教材学习会话和正式刷题证据继续分区，只有进入既有正式 Practice 闭环的作答才能写入正式 L1。

### 5.4 逻辑数据模型

| 模型 | 关键内容 |
| --- | --- |
| `study_plan_textbook_binding` | 学习计划版本、教材版本、角色、优先级、状态、确认者和确认时间 |
| `objective_textbook_section_mapping` | Taxonomy 知识点、教材章节、置信度、创建方式、确认状态、映射版本 |
| `learning_source_snapshot` | 会话 ID、计划版本、知识点、教材版本集合、章节范围、索引版本 |
| `assessment_source_snapshot` | 试卷版本/题目版本、固定教材证据引用、生成时索引版本 |

约束：

- 绑定必须指向明确的学习计划版本和教材版本，不能只绑定“最新版”。
- 同一计划版本内的优先级必须确定性排序。
- 会话和试卷使用 source snapshot，保证恢复、重试与复盘时来源不漂移。
- mapping 与 binding 使用显式状态，不用空值或隐式 fallback 表示“已确认”。

### 5.5 技术方案

#### 5.5.1 两阶段检索

```text
知识点标题、目标和当前对话
  → 第一阶段：在已映射章节或绑定教材目录中定位候选章节
  → 第二阶段：仅在候选章节内部检索片段
  → 按教材权威等级、语义相关性和定位质量重排
  → 形成带 provenance 的有限证据包
  → DeepTutor Agent 生成讲解和引用
```

这样可以避免在大教材全集上进行无约束搜索，也避免把整本书装入 Prompt。证据包必须设置数量和 token 预算，并保留未截断的来源引用。

#### 5.5.2 中性会话 Host Hook

现有插件请求需要中性扩展，以支持：

- 创建会话时携带 `knowledge_bases` 或等价的不透明知识源引用。
- 恢复已有会话时重新绑定经过权限验证的知识源和 source snapshot。
- 向 Agent 提供允许检索的 source/section filter，而不是把 ExamMem 数据库暴露给 Core。
- 将引用信息通过通用响应事件返回 Web、HTTP 和 SDK。

接口命名必须面向通用知识源和会话上下文，不能出现 `exam_mem` 条件分支。

#### 5.5.3 冲突识别

- 首先依靠确定性的来源优先级决定考试口径。
- 在同一知识点下分别抽取各教材的相关证据，由 LLM 生成结构化“相同/补充/冲突/无法判断”判断。
- 判断结果包含每项主张的 source references，不覆盖原文，也不自动修改优先级。
- 冲突判断可以缓存，但教材版本、章节映射或模型契约变化后必须失效重算。
- 无法判断时返回“无法判断”，不得无限调用或退化为无来源回答。

### 5.6 预期难点与处理原则

| 难点 | 风险 | 处理原则 |
| --- | --- | --- |
| 教材目录与考试大纲结构不同 | 错误一一对应 | 使用多对多映射和确认状态，不共享 ID |
| 自动映射误匹配 | 学习检索跑偏 | 推荐不等于确认；展示覆盖率和证据 |
| 多本教材检索噪声 | Prompt 过长、回答混乱 | 章节路由、来源分组、优先级重排、token 预算 |
| 教材观点冲突 | 教学与判题不一致 | 固定权威顺序、显式冲突、题目证据快照 |
| 会话恢复后来源变化 | 同一学习路径前后口径漂移 | source snapshot 固定教材和索引版本 |
| 教材更新或归档 | 历史引用失效 | 不可变版本、软归档、历史只读访问 |
| RAG 无结果或低相关 | 模型产生无依据内容 | 明确无证据状态；通用知识单独标记 |
| 引用定位不准确 | 用户无法核对 | 引用返回章节路径、页码、片段和原始来源 |
| 正式记忆污染 | 闲聊或教材内容被当作掌握证据 | 只有 Practice 作答写正式 L1，其他来源分区 |

### 5.7 Checkpoint 2 验收标准

#### 功能验收

- 一个学习计划版本能绑定 0、1、N 本教材，并设置稳定的角色和优先级。
- 用户能查看、确认和调整知识点—教材章节映射；未确认建议不会成为正式考试依据。
- 从知识点首次进入学习时自动加载对应教材上下文，再次进入能恢复同一会话和 source snapshot。
- 教学回答展示可打开的教材、版本、章节和页码/来源引用。
- 未绑定教材与检索无结果都有明确 UI 状态，现有通用学习路径仍可使用。
- 两本教材出现预置冲突时，系统按权威规则说明考试口径，并同时展示冲突来源；同级冲突不被静默吞掉。
- 若题目使用教材证据生成，复盘可以看到固定证据，重复判题不因索引更新改变来源边界。

#### 数据与可靠性验收

- 学习计划、教材、章节、会话和试卷之间的引用可以双向追溯。
- 教材发布新版本后，旧会话和旧试卷仍使用旧 source snapshot；新会话只有在显式选择后才使用新版。
- 恢复、重试和重复请求使用幂等键，不重复创建映射、会话或题目证据快照。
- 不同用户、不同学习计划的数据和检索范围保持隔离。
- 教材归档不破坏历史学习、复盘、Trace 或正式记忆 provenance。

#### 入口与工程验收

- Browser、HTTP 和 SDK 均可创建/读取教材绑定并打开基于教材的学习会话。
- 中性 Plugin API 契约测试覆盖首次创建、已有会话重绑定、权限失败和索引失效。
- Repository/PostgreSQL 集成测试覆盖绑定、映射、优先级、版本快照、归档和跨计划隔离。
- RAG 集成测试覆盖章节过滤、引用、无结果、多教材排序和冲突样例。
- 现有 Practice → Grade → Memory → Recommendation → Recovery/Correction 回归通过。
- DeepTutor 在不加载 ExamMem 时原生测试和生产构建通过。
- DeepTutor Core 无任何 `exam_mem` import、条件分支或测试特判。

## 6. 两个 Checkpoint 的交付顺序与门禁

### Checkpoint 1 完成门禁

只有同时满足以下条件才进入 Checkpoint 2：

1. 教材版本和章节树已成为稳定、可追溯的领域事实。
2. 大文件任务具备真实进度、幂等和恢复能力。
3. 章节感知索引可以独立重建。
4. 权限隔离和归档语义通过集成测试。
5. 未对现有学习、练习和记忆功能造成回归。

### Checkpoint 2 完成门禁

1. 绑定、映射、优先级和 source snapshot 均落在明确版本边界上。
2. 学习会话能够真实检索教材并返回可核对引用。
3. 多教材冲突不会被静默融合，出题与判题来源一致。
4. 正式 Learning Memory 没有被普通教材阅读或聊天污染。
5. Browser、HTTP、SDK、PostgreSQL、全量回归和 Web production build 全部通过。

## 7. 测试策略

| 测试层级 | 重点 |
| --- | --- |
| 单元测试 | 章节树构造、稳定 ID、优先级排序、映射状态、冲突分类、source snapshot |
| 契约测试 | Plugin Source Host、索引 Host、会话知识源绑定、引用事件 |
| Repository 测试 | 教材版本、章节、任务、绑定、映射、归档、幂等和权限 |
| PostgreSQL 集成测试 | 事务、唯一约束、并发重试、跨计划/用户隔离、migration head |
| RAG 集成测试 | 章节过滤、长教材检索、引用定位、多教材和无结果 |
| API 测试 | 上传、进度、列表、绑定、映射、打开/恢复学习会话 |
| Web 测试 | 教材库、结构预览、真实进度、映射确认、引用和冲突展示 |
| 端到端测试 | 导入教材 → 生成/绑定计划 → 学习 → 教材证据出题 → 作答 → 复盘 |
| 回归测试 | 无 ExamMem Host、无教材计划、现有 Practice/Memory/Review |

测试材料必须是自建、公开许可或经过脱敏的 fixture，不得将受版权保护的完整教材提交到仓库。

## 8. 明确延期项

以下内容不属于这两个 Checkpoint：

- 视频、音频、图片集、笔记和 PPT 的独立摄取产品。
- 自动购买、下载或绕过版权限制获取教材。
- 对所有扫描版教材承诺完美 OCR、公式或复杂排版恢复。
- 无需用户确认地自动绑定教材、自动决定同级权威冲突。
- 跨用户共享教材市场、公开教材推荐社区和协作批注。
- Learning Journey Memory 或把普通阅读行为直接写入正式 L1。
- 用教材数据库替换 ExamMem Taxonomy、Lifecycle Memory 或独立 PostgreSQL。
- 为兼容错误模型而增加无限 fallback、双写数据库或 ExamMem 专用 Core 分支。

## 9. 最终完成定义

两个 Checkpoint 全部完成后，用户应能：

1. 上传并管理保留原始结构的版本化教材，即使教材较大也能看到真实进度并从失败处恢复。
2. 从教材生成或补充学习计划，同时清楚区分教材目录与考试 Taxonomy。
3. 为学习计划显式绑定零本、一本或多本教材，并确认知识点到章节的映射。
4. 从知识点进入可恢复的 DeepTutor 学习会话，获得带教材版本、章节和页码引用的讲解。
5. 在教材冲突时看到权威口径、差异和双方证据，而不是得到来源不明的融合答案。
6. 使用固定教材证据进行后续出题、判题和复盘，同时保持现有 Learning Memory 事实边界与生命周期语义不变。

工程上必须继续满足插件化、独立存储、版本不可变、可恢复、可审计、幂等和无 ExamMem Core 耦合等现有不变量。
