# 阶段 07：接入刷题端到端链路

> 阶段性质：真实入口装配与下游行为闭环。  
> 前置条件：[阶段 06](./06_生命周期状态机与审计.md)验收通过。  
> 退出条件：出题到推荐的完整链路通过 DeepTutor 真实入口运行，并产生正确数据库和 Trace 副作用。  
> 阶段门禁：端到端接线未验证，不得进入[阶段 08](./08_评测体系与Baseline.md)。

## 1. 阶段目标

把前六阶段的独立能力接入 DeepTutor 真实运行时，完成：

```text
选择/生成题目
→ 学生作答
→ 答案判定
→ 知识点与错因分析
→ Learning Event 追加
→ Lifecycle 更新
→ Student Model 投影
→ 下一题推荐
→ 状态和依据查询
```

本阶段最重要的验收不是“页面能返回一段话”，而是同一个 `trace_id` 能串起入口事件、工具结果、LLM 调用、数据库事务、Memory 变化和推荐依据。

### 1.1 范围

本阶段只完成考研数学一线性代数与概率论的单用户练习闭环和必要 CLI/Web/API 入口；复杂多 Agent、真实支付/运营、微服务化和大规模并发不在范围内。Native Memory 只经 Adapter 调用，不改写其内部格式。

## 2. Capability 与 Tool 设计

### 2.1 `exam_practice` Capability

这是一个多阶段工作流，负责状态推进和用户交互，不把所有逻辑塞进一个 Tool：

```text
IDLE → QUESTION_READY → ANSWER_RECEIVED → GRADED
     → DIAGNOSED → MEMORY_UPDATED → RECOMMENDED
```

Capability 的上下文包含 `practice_session_id`、`scope`、当前题目、已提交答案、步骤状态和 `trace_id`。重试必须从已完成步骤恢复，不能重复判题或重复写事件。

### 2.2 单一职责 Tools

| Tool | 输入 | 输出 | 禁止事项 |
| --- | --- | --- | --- |
| Question Retriever | Scope、目标知识点、难度、排除题目 | `Question` | 不更新 Memory |
| Answer Grader | 题目、参考答案、学生答案 | `GradeResult` | 不直接推断长期掌握度 |
| Knowledge Mapper | 题目、解法、taxonomy version | canonical IDs | 不创建自由 taxonomy |
| Error Analyzer | 判题证据、答案步骤、候选词表 | `DiagnosisResult` | 不执行数据库更新 |
| Memory Reader | Scope | `StudentModel`/候选 | 不跨 Scope 查询 |
| Memory Writer | `LearningEvent` | `LifecycleDecision` | 不绕过状态机 |
| Recommendation Tool | Student Model、题库状态、计划 | `Recommendation` | 不直接读 archived Memory |

Tool 输出全部使用 Pydantic/JSON Schema。失败返回结构化 error code，不把 traceback 当成模型上下文。

## 3. 核心数据接口

```python
class Question(BaseModel):
    question_id: str
    stem: str
    knowledge_point_ids: list[str]
    difficulty: float
    reference_answer: str
    grading_rubric: dict

class AnswerSubmission(BaseModel):
    practice_session_id: str
    question_id: str
    answer: str
    submitted_at: datetime
    idempotency_key: str

class GradeResult(BaseModel):
    correct: bool
    score: float
    matched_rubric_items: list[str]
    missed_rubric_items: list[str]
    evidence: list[str]
    grader_version: str

class DiagnosisResult(BaseModel):
    knowledge_point_ids: list[str]
    error_type: str | None
    explanation: str
    confidence: float
    analyzer_version: str

class Recommendation(BaseModel):
    question_id: str
    target_knowledge_point_id: str
    target_difficulty: float
    reason_codes: list[str]
    source_memory_ids: list[str]
    policy_version: str
```

参考答案、评分点和学生答案在进入 LLM 前必须明确分隔，避免把学生答案中的指令当系统指令。

## 4. 技术路线与端到端数据流

### 4.1 开始练习

1. 从 DeepTutor CLI/Web/API 进入 `exam_practice`；
2. 解析并验证 `MemoryScope`；
3. 根据 Feature Flag 构造唯一 `MemoryBackend`；
4. 查询当前 Student Model；
5. Recommendation Tool 选择知识点、难度和题目；
6. 保存 practice session 状态并返回题目。

### 4.2 提交答案

1. 使用 `idempotency_key` 防止重复提交；
2. Answer Grader 输出评分证据；
3. Knowledge Mapper 归一 taxonomy；
4. 错题或有价值的答对轨迹进入 Error Analyzer；
5. 组合为使用三维 `LearningContext` 的 `LearningEvent`，先追加一次 L1；
6. 从该事件派生一个或多个携带完整四维 Scope 的 `MemoryUpdateCandidate`，Backend 根据模式执行无记忆、原生、追加、向量或生命周期更新；
7. 更新/重建 L3；
8. 生成下一题推荐并返回“为什么推荐”。

判题失败时不写“答错”事件；诊断失败时可写包含判题事实但 `error_type=unknown` 的 L1，不能猜测错因。Memory 更新失败不篡改判题结果，但返回可重试状态并记录告警。

## 5. 可解释推荐策略

MVP 不让 LLM 自由挑题。对每个候选知识点计算版本化优先级：

```text
priority =
  0.40 × weakness
+ 0.25 × stable_error
+ 0.15 × forgetting_risk
+ 0.10 × active_plan_priority
+ 0.10 × coverage_gap
```

所有特征归一到 `[0, 1]`。这些权重是 `recommendation_policy_v1` 的工程默认值，需在开发集做敏感性分析，不得声称是学习科学最优权重。

约束：

- archived/invalidated Memory 不参与；
- contested 证据以低权重参与，并在 reason code 标记；
- 最近连续练习的知识点施加去重惩罚，控制过度复习；
- 题目难度围绕当前 mastery 选择，不用“越难越好”；
- 无 Memory 时按固定 syllabus 顺序和题库难度作为确定性回退；
- 推荐结果必须记录 `source_memory_ids`、特征值、总分和 tie-break 规则。

## 6. Trace 与可观测性

每次 practice turn 使用同一 `trace_id`，每个步骤有单调 `step_id`：

```text
request_received
question_selected
answer_graded
knowledge_mapped
error_diagnosed
event_appended
lifecycle_decided
lifecycle_applied
student_model_projected
question_recommended
response_sent
```

每个 span 记录：状态、输入输出摘要、版本、耗时、重试次数、LLM calls、input/output tokens、错误码和相关记录 ID。学生答案和 LLM 原文按隐私策略脱敏，不在普通 INFO 日志完整打印。

## 7. 失败与重试

| 失败点 | 行为 |
| --- | --- |
| 题库无候选 | 返回明确错误和可用知识点，不生成虚构题目 |
| 判题结构化输出非法 | 有限重试；仍失败则不写学习结论 |
| Knowledge Mapper 低置信度 | L1 保留，canonical ID 为 unknown，进入复核 |
| L1 幂等重复 | 读取已有结果并继续，不重复计证据 |
| 生命周期 CAS stale | 最多重算 2 次，之后返回可重试错误 |
| L3 投影失败 | 保留 L1/L2，记录 watermark 并异步/手动重试 |
| 推荐失败 | 使用固定 syllabus 回退，标记 fallback reason |
| 客户端重复提交 | 返回第一次已完成结果 |

工作流必须持久化关键 checkpoint，不能因为 WebSocket 断开而重复写 Memory。

## 8. 端到端测试

### 8.1 Happy Path

- 弱点知识题目 → 答错 → 概念错因 → ADD/MERGE → 推荐同域较易题；
- 连续进步 → SUPERSEDE 旧 weak 状态 → 推荐难度提升；
- 计划完成 → INVALIDATE → 不再因旧计划推荐；
- 高掌握度后单次粗心 → CONTESTED/保守更新 → 不立即降为 low。

### 8.2 Backend 模式

同一条轨迹分别运行五种模式，验证：入口和题目相同、Trace 结构相同、Memory 副作用符合阶段 02 矩阵。

### 8.3 主链路接线证明

测试必须从真实 CLI/Web/API 入口发起，并断言：

- Registry 确实选择 `exam_practice`；
- Tool 调用顺序正确；
- PostgreSQL 新增 L1、L2、provenance、decision/change log；
- L3 watermark 推进；
- 推荐引用刚刚更新的状态；
- Trace 中的 ID 能反查数据库记录；
- 重复请求不增加事件、版本或证据数。

只 mock 掉所有 Repository 的测试不能作为本阶段端到端验收。

## 9. 引导式编程任务

### 任务 A：画状态图再写 Capability

先手工画出七个状态及失败/恢复边，写一个“重复提交不会重复更新”的失败测试，再实现工作流。AI Review 检查恢复语义，不替你写整条链路。

### 任务 B：实现可解释推荐

对三个知识点手算 priority，预测下一题，再运行代码比较。能够解释每项特征、权重和 tie-break 后才接真实题库。

### 任务 C：证明真实副作用

从 CLI 或 API 发起一次答题，使用 Trace ID 查询 L1/L2/L3 和审计表。故意断开客户端并重放请求，确认没有重复版本。

## 10. 运行命令模板

以下是目标接口模板，阶段实现时应与锁定 DeepTutor CLI 风格对齐并回填真实参数：

```powershell
# 启动依赖与后端
docker compose up -d postgres
deeptutor serve --port <PORT>

# 发起练习；具体 capability 参数以实现为准
deeptutor run exam_practice "开始数学一概率论练习" --format json

# 运行端到端测试
pytest -m "e2e and exam_mem" -q

# 按 Trace 查询状态；命令名由实现阶段固化
python -m exam_mem.cli trace show <TRACE_ID>
python -m exam_mem.cli memory state --user <USER_ID> --subject math_1
```

不得为了让文档命令看起来完整而声称未实现的命令已经可用；阶段交付时用真实命令替换模板。

### 11.2 验收标准

| 验收项 | 目标值 |
| --- | --- |
| Happy Path | 规定场景 100% 通过 |
| 五种 Backend | 行为与模式矩阵一致 |

| 数据库副作用 | 与 Gold 操作和状态一致 |

回滚方式：关闭 `exam_mem.enabled` 或切换 `memory_backend=native/none`；Learning Memory 数据保留用于审计，不自动删除。
