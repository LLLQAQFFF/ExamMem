## 一、关键结论

1. 这是一个仍在快速迭代的工程仓库（约 5500 次提交、15+ 作者、2026 年 3 月至 8 月），**没有任何可核验的“正式上线/灰度/验收通过”记录**。
2. **没有任何已入库的量化评测结果**。评测框架、数据制备脚本、数据集配置都在，但结果未执行/未入库，全部指标为“未查到数据”。
3. 唯一有据可查的真实效果是 2026-05-03 的四场景端到端实测（真实模型）：2 个场景通过，2 个场景失败（旧事实未归档、召回命中不足 60%），属“离线实测记录”而非最终效果。
4. 新一代八阶段治理管线（候选→回填→规划→决策日志→执行→投影失效→场景投影→收尾）**已实现且单测覆盖，但仅作为影子管线运行，未接入生产主链路**。
5. 生产冲突治理实际走两条旧路径：业务侧触发的轻量链路（三路召回 + 模型仲裁 + 校验 + 归档）和完整离线整理的纯算法治理（含地址类关键词兜底）。
6. **CAS 未接入主链路**：仅新一代管线内有行版本预检（未上线）；生产路径为盲版本号自增，或写前状态重检（无版本列、覆盖式写入）。
7. 决策日志属于新一代影子管线内部契约（计划/检查点/结果快照 + 恢复），生产只有审计痕迹，不是完整日志。
8. 业务级回滚**存在**：单用户备份/替换恢复 + 失败补偿已实现并有测试，但未对业务侧暴露，使用情况未查到。
9. “不确定样本保留双方”（CONTESTED）已实现，但**无收敛机制**，属已知遗留问题。
10. 仓库自身已承认：新旧两套实现骨架并存、文档与生产不一致、更新/删除生命周期不统一。

## 二、业务与架构

- **定位**：面向 Agent 系统的长期/短期记忆管理引擎，服务上层 Agent 运行时与端侧采集方，用于跨会话事实记忆、场景/项目记忆、离线记忆治理和检索注入。
- **数据来源**：用户对话（主）、工具结果与任务状态（部分）、端侧行为数据（浏览/收藏/待办）。
- **数据流**：窗口聚批 → 模型统一提取（分类/场景标签/槽位键/时间归一）→ 候选召回 → 冲突消解 → 落库（向量+关键词索引）→ 离线治理（场景涌现/冲突治理/衰减压缩/归档）→ 检索注入。
- **同步路径**：立即写入 + 去重消解；**异步路径**：对话队列窗口批处理；**离线路径**：外部触发（手动/定时/业务侧），系统零自触发、无固定频率。
- **离线三阶段**：候选扫描与向量预热 → 场景提案（模型聚类）→ 场景行写库；失败按阶段降级不中断。
- **运行时**：同步写入、异步摄入、离线治理、检索四类路径均已实现并接线；**是否真实上线均未查到证据**。

## 六、稳定性与安全

- **无 CAS 的并发防护**：单实例运行锁 + 用户级隔离 + 写前状态重检；已知风险：并发写回仍可能相互覆盖。
- **失败补偿**：新写入失败不阻塞业务；归档后血缘/日志写失败无补偿；变更日志写失败不回滚业务写。
- **幂等**：队列水位、来源键幂等、运行租约、恢复快照。
- **降级**：模型不可用时整窗原文兜底写入（兜底后不再重新解析）；非法输出按降级处理不中断；预算控制存在。
- **删除**：软删 + 关联索引/摘要/血缘清理；无物理删除，归档保留期无策略。
- **主要已知缺陷**：无 CAS、固定阈值、存疑不收敛、槽位键无二次校正、兜底不重解析、更新/删除生命周期不统一、新旧两套实现并存、所有效果指标缺失。
- 附注：仓库配置文件中存在疑似明文密钥（可能为开发环境密钥），建议确认是否泄漏。
